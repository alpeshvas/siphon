Siphon

A minimal DSL for extracting data from JSON APIs. Like a siphon draws liquid from a container, Siphon draws the data you need from nested JSON structures — just define the paths, and let it flow.

API layers

Three progressively powerful APIs

APIVersionUse Case
process() v0.4+ Simple flat extraction with paths, filters, and projection
query() v0.6+ Hierarchical chaining, MongoDB-style filters, sort, limit
pipeline() v0.7+ Multi-stage extraction with cross-references between stages

Installation

$ pip install siphon-dsl

$ pip install siphon-dsl[http] adds requests for fetch_and_process
$ pip install siphon-dsl[typed] adds pydantic for typed specs

Quick Start

from siphon import process

data = {
    "data": {
        "id": "prod_123",
        "items": [
            {"id": 1, "status": "active", "name": "Widget"},
            {"id": 2, "status": "inactive", "name": "Gadget"},
            {"id": 3, "status": "active", "name": "Thing"},
        ],
    }
}

spec = {
    "extract": {
        "id": "$.data.id",
        "all_active": {
            "path": "$.data.items[*]",
            "where": {"status": "active"},
            "select": {"item_id": "id", "item_name": "name"},
            "collect": True,
        },
    }
}

result = process(spec, data)
# {"id": "prod_123", "all_active": [{"item_id": 1, ...}, {"item_id": 3, ...}]}

Architecture

Siphon provides three API layers, each building on the one below:

+---------------------------------------------+ | pipeline() v0.7.0+ | | Multi-stage, GitHub Actions-style | | Cross-references via $stages.<id>.<field> | +---------------------------------------------+ | query() v0.6.0+ | | Hierarchical chaining with "then" | | MongoDB-style filters, sort, limit, offset | +---------------------------------------------+ | process() v0.4+ | | Legacy flat extract API | | Simple path, where, select, collect | +---------------------------------------------+

Data Flow

Input Processing Output ------ ------------ ------ JSON data --> Path Resolution --> dict + (dot notation, [*]) list Spec --> Filtering --> scalar (where / $operators) None --> Sort / Offset / Limit --> Projection (select)

Path Syntax

Siphon uses JSONPath-like dot notation to traverse JSON structures.

PathDescriptionExample
$.data.id Nested value access Returns the value at data.id
data.id Same (the $. prefix is optional) Equivalent to $.data.id
$.items[*].name Array iteration Returns name from each item
$.a[*].b[*].c Multi-level nested arrays Traverses nested arrays recursively
$.items[*].pricing.amount Nested access within array items Accesses nested object in each item

Important

Without collect: true, array paths return the first match only. Use collect: true to get all matches as a list.

Spec Format

A spec is a dictionary with an extract key containing field definitions. Each field can be a simple string path or an extended object.

spec = {
    "extract": {
        "id": "$.data.id",          # simple string path
        "name": "$.data.name",      # nested access
    }
}
spec = {
    "extract": {
        "active_items": {
            "path": "$.data.items[*]",
            "where": {"status": "active"},
            "select": {"item_id": "id", "item_name": "name"},
            "collect": True,
        }
    }
}
@dataclass
class FieldSpec:
    path: str                    # Required: JSONPath expression
    where: dict | None = None    # Optional: filter conditions
    select: dict | None = None   # Optional: {output: "path" or "path1 || path2 || ..."}
    collect: bool = False        # Optional: return all matches
    reduce: str | dict | None = None  # Optional: aggregate to single value

process() Legacy API · v0.4+

The foundational extraction API. Pass a spec with an extract key and get back a dictionary of extracted values.

from siphon import process

result = process(spec, data)  # returns dict

Filtering with where

Filter array items by field values. Multiple conditions use AND logic.

"active_item": {
    "path": "$.data.items[*]",
    "where": {"status": "active"}        # simple equality
}

"premium_active": {
    "path": "$.data.items[*]",
    "where": {
        "status": "active",               # multiple = AND logic
        "tier": "premium"
    }
}

"expensive": {
    "path": "$.data.items[*]",
    "where": {"pricing.amount": 100}   # dot notation in keys
}

Projection with select

Rename and reshape extracted fields.

"item": {
    "path": "$.data.items[*]",
    "select": {
        "item_id": "id",             # rename id -> item_id
        "item_name": "name",         # rename name -> item_name
        "cost": "pricing.amount",     # nested access in select
        "curr": "pricing.currency"
    }
}
# Input:  {"id": 1, "name": "Widget", "pricing": {"amount": 100, "currency": "USD"}}
# Output: {"item_id": 1, "item_name": "Widget", "cost": 100, "curr": "USD"}

Coalesce with || v0.10+

A select path string can contain || to declare a SQL-style fallback chain. Segments are tried left-to-right; the first one resolving to a non-None value wins; if all are None, the field is None. Any number of segments is supported. Useful for fallback values (e.g. sale price → list price).

"products": {
    "path": "$.products[*]",
    "select": {
        "id": "id",
        "price": "sale_price || list_price",   # fall back if sale_price is null
        "label": "customLabel || title || ticketCategory"
    },
    "collect": True
}
# Input:  [{"id": 1, "sale_price": 8.0, "list_price": 10.0},
#          {"id": 2, "sale_price": null, "list_price": 15.0}]
# Output: [{"id": 1, "price": 8.0, ...}, {"id": 2, "price": 15.0, ...}]
All segments resolveResult
first non-Nonethat value (stops searching — 0, "", False count as non-None)
all None / missingNone
whitespace around ||ignored
empty segment (e.g. "|| a")skipped

By default, extraction returns the first match. Set collect: true to get all matches.

Ancestor Filtering v0.5+

When extracting from nested arrays, where can match properties from any parent level, not just the innermost item.

# Filter passengers by their parent rate's rateId
"passengers": {
    "path": "$.pricesByDateRange[*].rates[*].passengers[*]",
    "where": {"rateId": 1760309},  # rateId is on rate, not passenger!
    "select": {
        "title": "title",
        "amount": "price.amount",
        "currency": "price.currency"
    },
    "collect": True
}

How ancestor context works

As Siphon traverses nested arrays, it merges properties from each level into a context. If the same property name exists at multiple levels, the innermost value wins.

Aggregation with reduce v0.8+

Instead of collecting all values and post-processing in application code, reduce collapses an array path into a single computed result. It is mutually exclusive with collect.

# Earliest time-of-day across items on any date (timezone ignored)
"earliest_slot": {
    "path": "$.data.items[*].availability_from_date_time",
    "reduce": "min_time"
}

# Sum of all prices
"total": {
    "path": "$.products[*].price",
    "reduce": "sum"
}

# Deduplicated list of categories
"categories": {
    "path": "$.products[*].category",
    "reduce": "distinct"
}

# Concat with a custom separator (dict form)
"tag_list": {
    "path": "$.tags[*].name",
    "reduce": {"op": "concat", "sep": " | "}
}
OperatorInput typeDescription
min_time / max_timeISO 8601 datetime or plain HH:MM / HH:MM:SSEarliest/latest time-of-day — ignores date and timezone plain-time support: v0.9+
min_date / max_dateISO 8601 datetime/dateEarliest/latest calendar date — ignores time
min_datetime / max_datetimeISO 8601 datetimeEarliest/latest full datetime, timezone-normalised
min_int / max_intnumberMinimum/maximum numeric value (int or float)
sumnumberSum of all values
countanyCount of non-null values — returns 0 for empty (not None)
first / lastanyFirst or last value in traversal order

distinctanyDeduplicated list, preserving first-seen order

query() Chaining API · v0.6+

The chaining query engine adds hierarchical extraction, MongoDB-style filter operators, sorting, and pagination.

from siphon import query

spec = {
    "from": "$.items[*]",
    "where": {"price": {"$gt": 50}},
    "select": {"id": "item_id", "cost": "price"},
    "sort": [{"field": "price", "order": "asc"}],
    "limit": 10,
    "collect": True,
}
result = query(spec, data)

Filter Operators

MongoDB-style operators for expressive filtering:

OperatorDescriptionExample
$eqEqual (default for bare values){"status": {"$eq": "active"}}
$neNot equal{"status": {"$ne": "deleted"}}
$gtGreater than{"price": {"$gt": 50}}
$gteGreater than or equal{"price": {"$gte": 50}}
$ltLess than{"price": {"$lt": 100}}
$lteLess than or equal{"price": {"$lte": 100}}
$inIn a list{"status": {"$in": ["active", "pending"]}}
$ninNot in a list{"status": {"$nin": ["deleted"]}}
$existsField exists (not None){"email": {"$exists": true}}
$regexRegex match{"name": {"$regex": "^Pro"}}

Logical Operators

# $and - all must match
"where": {"$and": [{"price": {"$gt": 10}}, {"price": {"$lt": 100}}]}

# $or - at least one must match
"where": {"$or": [{"status": "active"}, {"featured": True}]}

# $not - negate a condition
"where": {"$not": {"status": "deleted"}}

# $nor - none must match
"where": {"$nor": [{"status": "deleted"}, {"status": "archived"}]}

Sort & Pagination

{
    "from": "$.products[*]",
    "sort": [
        {"field": "price", "order": "desc"},   # primary sort
        {"field": "name", "order": "asc"}      # secondary sort
    ],
    "offset": 5,    # skip first 5
    "limit": 10,    # return at most 10
    "collect": True
}

None values always sort last, in both ascending and descending order.

Then Chaining

Use then to create hierarchical, multi-level extractions. Intermediate-level select fields are carried forward to child results.

{
    "from": "$.categories[*]",
    "select": {"category": "name"},        # carried to children
    "then": {
        "from": "products[*]",              # relative path
        "where": {"inStock": True},
        "select": {"name": "name", "price": "price"},
        "collect": True
    }
}
# Result: [{"category": "Electronics", "name": "Phone", "price": 999}, ...]

Carry-forward semantics

When using then, fields projected at an intermediate level are merged into each child result. On key collision, child values win.

Multi-star auto-decomposition

Paths with multiple [*] like $.a[*].b[*].c are automatically decomposed into nested chain specs, so you don't need to manually nest then blocks.

pipeline() Pipeline API · v0.7+

GitHub Actions-style multi-stage pipeline where stages can cross-reference each other's outputs.

from siphon import pipeline

stages = [
    {
        "id": "rate",
        "from": "$.rates[*]",
        "where": {"id": 1},
        "select": {"startTimeIds": "startTimeIds"},
    },
    {
        "from": "$.startTimes[*]",
        "where": {"id": {"$in": "$stages.rate.startTimeIds"}},
        "collect": True,
        "select": {"hour": "hour", "minute": "minute"},
    },
]

result = pipeline(stages, data)

Stage References

Reference prior stage outputs with $stages.<id>.<field> in where clauses.

Key BehaviorDescription
Each stage resolves against root dataNot previous stage output
List stage outputField is gathered from all items in the list
Dict stage outputField is extracted directly
Return valueThe last stage's output
Pipeline Execution Stage 1 ("rate") Stage 2 +----------------+ +-------------------+ | from: rates[*] | | from: startTimes | | where: {id: 1} | | where: id $in | | select: ids |--->| $stages.rate.ids | +----------------+ +-------------------+ | | resolves vs resolves vs root data root data

Typed API (Pydantic) Optional

Pydantic models provide validation, serialization, and schema generation for specs. Requires pip install siphon-dsl[typed].

from siphon.typed import process_spec, ExtractSpec, FieldSpec

spec = ExtractSpec(
    extract={
        "id": "$.data.id",
        "active_items": FieldSpec(
            path="$.data.items[*]",
            where={"status": "active"},
            select={"item_id": "id", "name": "name"},
            collect=True,
        ),
    }
)

result = process_spec(spec, data)
from siphon.typed import query_typed, ChainSpec, SortSpec

spec = ChainSpec(
    from_="$.items[*]",         # from_ because from is a Python keyword
    where={"status": "active"},
    select={"id": "item_id"},
    sort=[SortSpec(field="price", order="desc")],
    limit=5,
    collect=True,
)

result = query_typed(spec, data)
from siphon.typed import pipeline_typed, PipelineSpec, ChainSpec

spec = PipelineSpec(
    stages=[
        ChainSpec(
            id="rates",
            from_="$.rates[*]",
            where={"id": 1},
            select={"timeIds": "startTimeIds"},
        ),
        ChainSpec(
            from_="$.startTimes[*]",
            where={"id": {"$in": "$stages.rates.timeIds"}},
            select={"hour": "hour"},
            collect=True,
        ),
    ]
)

result = pipeline_typed(spec, data)

Fetch & Process

Fetch JSON from an API endpoint and extract in one step. Requires pip install siphon-dsl[http].

from siphon import fetch_and_process

spec = {
    "request": {"path": "/api/v1/products"},
    "extract": {
        "id": "$.data.id",
        "names": {"path": "$.data.items[*].name", "collect": True},
    },
}

result = fetch_and_process(spec, "https://api.example.com")

YAML Specs

Siphon specs are data, so they can be stored as YAML files and loaded at runtime.

# products.siphon.yaml
version: "0.5"

request:
  path: "/api/v1/products"

extract:
  product_id: "$.data.id"

  active_variants:
    path: "$.data.variants[*]"
    where:
      status: "active"
      inStock: true
    select:
      sku: "sku"
      name: "displayName"
      price: "pricing.retail"
    collect: true
import yaml
from siphon import fetch_and_process

with open("products.siphon.yaml") as f:
    spec = yaml.safe_load(f)

result = fetch_and_process(spec, "https://api.store.com")

Projection Rules

  • select only applies when extracting objects (not scalars)
  • Dot notation supported in source paths: {"cost": "pricing.amount"}
  • Missing fields become None
