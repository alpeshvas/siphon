# Siphon Spec v0.11

Extends path strings with `[N]` list indexing. Any dot-separated segment of a path may end with one or more `[N]` indices to drill into a list at a specific position. Negative indices are allowed. Out-of-bounds indices, missing keys, and indexing into non-list values all resolve to `None`.

This applies everywhere paths are resolved: `select` projections, `where` field keys, top-level `extract` paths, chain `from` prefixes, and `reduce` field references.

## Overview

Prior versions supported `[*]` for "iterate every element" but had no way to address a single list position from inside a path. v0.11 adds `[N]` for direct indexing.

```python
spec = {
    "extract": {
        "row": {
            "path": "$.items[*]",
            "select": {
                # Pick the first tier's amount; fall back to a flat price
                "amount": "tieredPrices[0].amount || price.amount",
            },
        }
    }
}
```

Indexing composes with the existing `||` coalesce operator, so a single `select` expression can target both shapes.

---

## Path Indexing

A path segment can carry one or more `[N]` indices appended to the field name (or used alone after a dot). Each `[N]`:

- Accepts any integer literal, including negatives (`[-1]` is the last element).
- Returns `None` if the current value is not a list.
- Returns `None` if the index is out of bounds.
- May be chained: `matrix[0][1]` drills into a list of lists.

The existing `[*]` iteration syntax is unchanged and remains separate — `[*]` says "iterate every element"; `[N]` says "take element N".

### Supported forms

| Syntax                          | Meaning                                         |
| ------------------------------- | ----------------------------------------------- |
| `items[0]`                      | First element of `items`                        |
| `items[-1]`                     | Last element                                    |
| `items[0].id`                   | Field `id` on the first element                 |
| `matrix[0][1]`                  | Nested index                                    |
| `a.b[2].c`                      | Mixed dots and indices                          |
| `tieredPrices[0].amount \|\| price.amount` | Coalesce across indexed and flat paths |

## Examples

### Pick a specific tier in a `select`

```python
data = {"items": [{"tieredPrices": [{"amount": 50}, {"amount": 100}]}]}
spec = {"extract": {"first_tier": {"path": "$.items[*]", "select": {"v": "tieredPrices[0].amount"}}}}
# -> {"first_tier": {"v": 50}}
```

### Coalesce across shapes (tiered vs flat)

```python
tiered     = {"tieredPrices": [{"amount": 99}], "price": {"amount": 5}}
non_tiered = {"tieredPrices": [],               "price": {"amount": 7}}
data = {"items": [tiered, non_tiered]}

spec = {
    "extract": {
        "out": {
            "path": "$.items[*]",
            "select": {"amount": "tieredPrices[0].amount || price.amount"},
            "collect": True,
        }
    }
}
# -> {"out": [{"amount": 99}, {"amount": 7}]}
```

### Index in a top-level extract path

```python
data = {"items": [{"id": 1}, {"id": 2}, {"id": 3}]}
spec = {"extract": {"second": "$.items[1].id"}}
# -> {"second": 2}
```

### Negative index

```python
data = {"items": [{"names": ["a", "b", "c"]}]}
spec = {"extract": {"out": {"path": "$.items[*]", "select": {"v": "names[-1]"}}}}
# -> {"out": {"v": "c"}}
```

## Behavior Reference

| Condition                                   | Result |
| ------------------------------------------- | ------ |
| Index in-bounds on a list                   | element at that position |
| Negative index in-bounds                    | element counted from end |
| Index out of bounds                         | `None` |
| Field before `[N]` is missing               | `None` |
| Indexing into a non-list (dict/scalar/None) | `None` |
| Multiple chained `[N][N]`                   | left-to-right drill, `None` on any failure |
| `[N]` combined with `||` coalesce           | first non-`None` alternative wins |
| `[*]` semantics                             | unchanged — still iterates |

---

## Changes from v0.10

- **New**: `[N]` indexing supported anywhere `get_by_path` is used (select, where keys, top-level extract paths, chain `from` prefixes, `reduce` fields).
- **Unchanged**: `[*]` iteration, `||` coalesce, all other v0.10 behavior.
- **No breaking changes**. Paths without `[N]` resolve identically to v0.10.
