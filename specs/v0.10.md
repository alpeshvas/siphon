# Siphon Spec v0.10

Extends `select` path strings with a SQL-style `||` coalesce operator. A path like `"sale_price || list_price"` resolves left-to-right and returns the first segment whose value is not `None`. The single-path form is unchanged.

## Overview

`select` projects and renames fields on each matched item. Each entry maps an output name to a source path. As of v0.10, a path string may contain `||` to declare a fallback chain — equivalent to `COALESCE(path1, path2, ...)` in SQL.

```python
spec = {
    "extract": {
        "row": {
            "path": "$.items[*]",
            "select": {
                # try `discounted_price` first; fall back to `price`
                "price": "discounted_price || price",
            },
        }
    }
}
```

The list-of-paths shape (`["a", "b"]`) is **not** used for coalesce — it is reserved for a possible future "build a list from these paths" feature.

## FieldSpec Schema

```python
@dataclass
class FieldSpec:
    path: str                              # Required: JSONPath expression
    where: dict | None = None              # Optional: filter conditions
    select: dict | None = None             # Optional: {output: "path" | "path1 || path2 || ..."}
    collect: bool = False                  # Optional: return all matches
    reduce: str | dict | None = None       # Optional: aggregation operator
```

Each `select` value is a string. The `||` separator (optionally surrounded by whitespace) splits the string into a fallback chain.

| Form | Behavior |
|---|---|
| `"some.path"` | Resolve a single path. |
| `"a || b || c"` | Coalesce — return the first non-`None` resolution; otherwise `None`. |

## Select Coalesce

### Single-path (pre-v0.10 form)

```python
"select": {"name": "title"}
```

Equivalent to `output["name"] = item.get("title")`.

### Pipe-coalesce (new in v0.10)

```python
"select": {"amount": "promo.amount || list.amount"}
```

Equivalent to:

```python
output["amount"] = item["promo"]["amount"]
if output["amount"] is None:
    output["amount"] = item["list"]["amount"]
```

Any number of segments is supported:

```python
"select": {"label": "customLabel || title || ticketCategory"}
```

### Resolution rules

1. Segments are evaluated left-to-right.
2. The first segment that resolves to a value **other than `None`** is used. `0`, `""`, `False`, and empty lists/dicts are all valid (non-`None`) values and stop the search.
3. If every segment resolves to `None` (including missing keys), the output field is `None`.
4. Whitespace around each segment is stripped, so `"a||b"`, `"a || b"`, and `"  a  ||  b  "` are equivalent.
5. Empty segments (e.g. from `"|| a"` or `"a ||"`) are skipped — they do not match the whole item.
6. Each non-empty segment uses the same dot-notation as a single-path `select` value.

A JSON key that literally contains the substring `||` is not addressable through this syntax. This is an accepted limitation.

---

## Behavior Reference

| Scenario | Result |
|---|---|
| All segments missing | `None` |
| First segment is `None`, second is `42` | `42` |
| First segment is `0`, second is `42` | `0` (zero stops the search) |
| Single-path form (no `||`) | Unchanged from v0.9 |
| Used inside `then` chain | Works at terminal *and* intermediate levels (intermediate uses the resolved value for carry-forward) |
| Whitespace around `||` | Ignored |
| Empty segment | Skipped |

## Examples

### Fallback pricing

```python
data = {
    "products": [
        {"id": 1, "sale_price": 8.0, "list_price": 10.0},
        {"id": 2, "sale_price": None, "list_price": 15.0},
    ]
}

spec = {
    "extract": {
        "products": {
            "path": "$.products[*]",
            "select": {
                "id": "id",
                "price": "sale_price || list_price",
            },
            "collect": True,
        }
    }
}

# {
#   "products": [
#     {"id": 1, "price": 8.0},
#     {"id": 2, "price": 15.0},
#   ]
# }
```

### Chain query with coalesce

```python
from siphon import query

data = {
    "groups": [
        {
            "primary_label": None,
            "secondary_label": "Adults",
            "items": [{"name": "ticket"}],
        }
    ]
}

spec = {
    "from": "$.groups[*]",
    "select": {"label": "primary_label || secondary_label"},
    "then": {"from": "items[*]", "select": {"name": "name"}, "collect": True},
}

query(spec, data)
# [{"label": "Adults", "name": "ticket"}]
```

## Changes from v0.9

### Added

- `select` path strings may now contain `||` to declare a coalesce/fallback chain. The first segment resolving to a non-`None` value wins.

### No breaking changes

All v0.9 specs are valid v0.10 specs. Path strings without `||` behave identically.
